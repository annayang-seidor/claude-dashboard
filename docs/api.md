# API

Every request needs `Host: 127.0.0.1:4317` (or `localhost:4317`) and `X-Dashboard-Token`. Non-GET requests also need an allowed `Origin` (ADR 0001). Schemas: `src/shared/api.ts`. Errors are `{ "error": string }`.

| Method | Path | Input | 200 response | Errors |
|---|---|---|---|---|
| GET | `/api/health` | none | `{ ok: true }` | 403 |
| GET | `/api/config` | none | `PageConfig`: `{ workspaces: [{ id, label, root, kind, fallback, autoArchiveDays }], cleanup: { ranges, defaultRange, customStartDays, keepBookmarked, keepTodo }, autoArchive: { enabled }, retentionWarnDays, undoMs }`, the page's part of the config read at start (ADR 0061) | 403 |
| GET | `/api/sessions` | query `workspace=<configured id>` (`work`, `personal` by default) | `{ sessions: ApiSession[] }`, newest activity first | 400 bad, missing or unconfigured workspace, 403 |
| GET | `/api/retention` | none | `{ cleanupPeriodDays: number \| null }`: Claude Code's value from `~/.claude/settings.json`, read on each call; 30 when unset or invalid, `null` when it is 0 (cleanup off) (ADR 0030) | 403 |
| GET | `/api/auto-archive` | none | `{ last: { at, moved: { <workspace id>: UUID[] } } \| null }`: what the last auto-archive run that moved anything moved, by workspace (ADR 0061), limited to ids still in the trash; `null` before the first such run (ADR 0037) | 403 |
| PATCH | `/api/sessions/:id` | `:id` UUID; JSON body with at least one of `status: "todo"\|"done"`, `bookmarked: boolean`, `categoryOverride: "ticket"\|"ops"\|"scratch"\|null` (null clears it), `title: string\|null` (trimmed, at most 120 characters; `null`, `""` or whitespace only clears the rename; ADR 0056); unknown keys rejected | the updated `ApiSession` | 400 bad id or body, 404 no live session with that id, 403 |
| POST | `/api/sessions/:id/resume` | `:id` UUID; no body | `{ ok: true }` once osascript has started | 400 bad id, 410 no transcript for that id (deleted, or never a session), 500 osascript could not start, 403 |
| POST | `/api/tickets/:key/new-session` | `:key` Jira key (`^[A-Z][A-Z0-9]+-\d+$`); optional JSON body `{ name?: string }`: trimmed, 1–120 characters, no control characters (checked before trimming, so a trailing newline is rejected too); passed as `claude --name`; no body or `{}` starts without a name; unknown keys rejected | `{ sessionId }`: the id passed to `claude --session-id` | 400 bad key, body not JSON, or invalid name (`invalid session name`; nothing is launched or stored), 500 osascript could not start (the state entry is removed), 403 |
| POST | `/api/sessions/:id/trash` | `:id` UUID; no body | `{ ok: true }`: the transcript, and its `<id>/` folder if any, are in `~/.claude-dashboard/trash/` | 400 bad id, 404 no live transcript, 409 the trash already holds that id, 500 the move failed (state is left as it was), 403 |
| POST | `/api/sessions/:id/restore` | `:id` UUID; no body | `{ ok: true }`: both are back where they were | 400 bad id, 404 no trash record, 409 the transcript or folder exists again, 410 the trashed files or the project folder are gone, 500 the move failed or the record points outside `~/.claude/projects`, 403 |
| POST | `/api/sessions/trash`, `/api/sessions/restore` | JSON `{ ids: UUID[] }`, 1–200 ids; unknown keys rejected | `{ results: [{ id, ok, error? }] }` in request order; `error` is `not-found`, `conflict`, `gone` or `failed` (the single-id 404/409/410/500) | 400 bad body, 403 |
| POST | `/api/trash/purge` | none | `{ purged: UUID[] }` | 403 |
| GET | `/api/jira/inbox` | none | `{ result: { syncedAt, items: JiraInboxItem[] } \| null, lastAttempt: { at, ok, reason?, detail?, promptVersion? } \| null, jiraBaseUrl: string \| null }`: the result and attempt from state.json (ADR 0042) and the config's `jiraBaseUrl`, read at start (ADR 0044, ADR 0060); never runs anything | 403 |
| POST | `/api/jira/inbox/sync` | none | the same, after a run (up to 120 s); runs at any time and joins a run already in flight | 403 |
| GET | `/api/events` | none; read with `fetch`, not `EventSource` (ADR 0013) | `text/event-stream`: `event: sessions-changed` / `data: {}` after transcripts change, plus a `: keep-alive` comment every 25 s | 403 |

`ApiSession` (ADR 0014) is the indexer's `Session` plus:
- `category`: the effective category (the override if set, otherwise the detected one)
- `autoCategory`: the detected category
- `state: { status, bookmarked, categoryOverride?, envOverride?, releaseLabel?, ticketOverride?, restoredAt?, title? }`; `restoredAt` is the last restore from the trash (ADR 0037); `title` is the dashboard rename when one is in force (ADR 0056)
- `ticketKey` is the state's `ticketOverride` when one is set (ADR 0025)
- `title`: the dashboard rename, else `autoTitle`. `autoTitle`: Claude Code's title, custom → ai → summary → first prompt (80 chars). `customTitle`: the last `custom-title` record anywhere in the transcript, or `null` (ADR 0055)

**Live updates:** the server watches `~/.claude/projects/*/*.jsonl`. It ignores sub-agent transcripts and the runner's folder. Changes are batched in a 500 ms window; each batch rescans, prunes, then sends `sessions-changed`. On that event, refetch `GET /api/sessions` (ADR 0015).

**Pruning:** on startup and after every rescan (including every `GET /api/sessions`), state for sessions that are gone is removed. Trashed entries are kept (ADR 0009). Nothing is pruned when the projects root cannot be read.

**Renames (ADR 0056):** a `title` PATCH re-indexes, then stores `title` and `titleSnapshot` (the session's `customTitle` at that moment, or `null`) in state.json. Right after pruning, each rescan drops both from any live session whose `customTitle` differs from its snapshot: it was renamed in Claude Code since, so its title shows again. A new `ai-title` changes only `autoTitle`. The dashboard never writes to the transcript.

**Pending sessions:** `new-session` writes `{ ticketOverride, pendingSince }` for the new id. Pruning spares it for 24 h until the transcript appears, then clears `pendingSince` (ADR 0025).

**Launching (Resume, New session):** each terminal is an adapter behind `Launcher` (`src/server/launch/`, ADR 0059); both current ones run `/usr/bin/osascript -e <script> <shell line>` as an argv array (spike Q9). The shell line is `cd <cwd> && claude --resume <id>` (or `claude --session-id <id> "Let's work on Jira ticket <KEY>."`), with each word single-quoted unless it is plain; the script reads it from `argv`, so it is never spliced into AppleScript. Resume uses the session's first cwd. New session uses the repo of the ticket's latest session, else the first Work-kind workspace root (ADR 0026, ADR 0061). The terminal is the config's `terminal`, read at start (ADR 0060):

| `terminal` | App | Tab or window | Not running |
|---|---|---|---|
| `iterm` (default) | iTerm2 | New tab in the current window; a new window if it has none | Launched; its first window is used (waits up to 5 s) |
| `terminal` | Terminal.app | Always a new window (a tab would need keystrokes) | Launched; its first window is used (waits up to 5 s), so no extra empty window |

Before spawning, the launcher checks that the app's bundle is in `/Applications`, `~/Applications` or `/System/Applications/Utilities`, and that the cwd has no control characters; either failure throws and the route answers 500, so osascript never shows a "Where is…" chooser. An AppleScript failure (for example, Automation permission denied) happens after the reply and is only logged.

**Trash (ADR 0009, ADR 0027, ADR 0031):** delete is a move, never an unlink. Trash writes `trashed: { originalPath, hadFolder, trashedAt }` to the session's state before moving the files, so status and bookmark survive pruning. Restore moves the files back, then clears the record. Restore also sets `restoredAt`, which restarts auto-archive's idle clock (ADR 0037). Trash, restore and purge run one at a time, and each success sends `sessions-changed`. Purge runs as a daily job (on start, then every `jobs.dailyIntervalHours`, 6 h by default, once per local day): it deletes recorded entries trashed over `trash.retentionDays` (7 by default) ago, along with their state, and any stray `<uuid>.jsonl` / `<uuid>/` in the trash with no record whose mtime is that old.

**Start-up (ADR 0028, ADR 0031, ADR 0032):** `src/server/start.ts` wires everything; `index.ts` passes the real paths and the token from `~/.claude-dashboard/token` (mode 600, kept across restarts; `pnpm start --rotate-token` makes a new one). After reading the config (see Config below), on start and then every `jobs.dailyIntervalHours` (6 h by default), the daily jobs run (trash purge, then auto-archive unless `autoArchive.enabled` is false), each at most once per local day, recorded under `jobs` in state.json. Once listening, the server writes the page link with the token to `~/.claude-dashboard/url` (mode 600). It logs `[startup] ready to serve after N ms` (counted from process start, so it includes the first index) and `[startup] first list (…) took N ms`. Either one goes to stderr with a note when it is over the 1 s target.

**Reconnect:** the page reads `/api/events` with `followEvents` (`src/web/api.ts`). When the stream ends or is refused, it retries after 1, 2, 4 … 30 s. The wait resets after each successful connect, and every reconnect refetches the list. After any 403 it stops for good, and the page shows "Server restarted — open the new link" (ADR 0032).

**Cleanup and auto-archive (ADR 0024, ADR 0037):** the Clean up modal and the `auto-archive` daily job share `selectCleanup` (`src/shared/cleanup.ts`). The modal picks sessions of its workspace last active before local midnight N days ago (`cleanup.ranges`, 7 or 14 by default) or before a custom date (today or earlier; the picker stops `cleanupPeriodDays` days back, ADR 0038). It keeps bookmarked and To do sessions unless unchecked, then trashes them with `POST /api/sessions/trash` in chunks of 200. Auto-archive trashes Scratch in each Work-kind workspace and every session in each Personal-kind one once idle over that workspace's `autoArchiveDays` (7 and 14 by default), counted from the later of `lastActivityAt` and `restoredAt`; bookmarked sessions are kept, To do sessions are not. A run that moves anything replaces `autoArchive` in state.json and sends `sessions-changed`. Every run appends one JSON line to `~/.claude-dashboard/activity.log` (mode 600): `{ at, job: "auto-archive", moved: [{ id, workspace, title }], failed: [{ id, error }] }`.

**Jira inbox (ADR 0042):** the `jira-inbox` job runs `claude -p` with `src/server/jobs/prompts/jira-inbox.md` (front matter `version: n`, `{{slots}}` filled by the server, read before every run). Changed issues are searched from the earlier of 2 days ago and the last good `syncedAt`, at most 7 days back; mentions from issues updated in the last 3 days. The runner sets `MAX_MCP_OUTPUT_TOKENS=60000` for `claude`, so a large search result stays inline instead of being saved under `~/.claude/projects` and read in part; the prompt answers a schema-failing `{"error":"search result too large"}` if one still is. The answer is validated with `JiraInboxResult` (`src/shared/state.ts`): spec fields, key `^[A-Z][A-Z0-9]+-\d+$`, ISO 8601 dates with a zone, reason 1–140 chars, at most 100 items, one per key. A valid answer replaces `sync.jira.result` whole, with `syncedAt` set to the run's start by the server clock; any other outcome only replaces `sync.jira.lastAttempt`. A background run starts on a 5-min tick when the local time is Mon–Fri 09:00–19:00 and the last attempt is at least 45 min old (so a restart does not run again). Every attempt sends `sessions-changed`.

**Jira base URL (ADR 0044, ADR 0058):** the config may set `"jiraBaseUrl": "https://<site>.atlassian.net"`. It must be https; trailing slashes are dropped. The inbox replies carry it (`null` when unset), and the page links a ticket to `<jiraBaseUrl>/browse/<KEY>`. An invalid value stops the server at start, as any invalid key does (ADR 0060).

**Config (ADR 0058, ADR 0060, ADR 0061):** `start()` reads `dashboard.config.json` (repo) then `~/.claude-dashboard/config.json` once, merges them key by key (the home file wins; lists are replaced), and throws `ConfigError` naming the file, key and expected value when either is invalid; `index.ts` prints it and exits 1. Every key has a default (`DEFAULT_CONFIG` in `src/shared/config.ts`); the README lists them. It then logs a `[config]` warning for each cleanup range or `autoArchiveDays` at or over Claude Code's `cleanupPeriodDays`.
